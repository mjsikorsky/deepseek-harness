# Agent Note: 动态 Host 代码准入

Status: implemented

[English](2026-09-13-dynamic-host-code-admission.md) | 中文

## 问题

动态 Host 包在共享 DSH 进程内执行。其 VM 和 Cordis façade 支持 API 正确性，并不隔离私有会话、凭据或其他 Host 资源。因此，会话协作权限不能授权任意 Host 源码，Client 对未来版本的批准也不能隐式授权新的 Host 代码。

## 决策

原生 runner 保留不可变包注册表、精确版本卡片以及 Host/Client 生命周期。共享部署通过显式配置要求 `cordisHostActivationPolicy`。provider 收到原生会话、插件、包和运行标识以及精确存储的 Host 源码。它从经过验证的部署上下文中确定提升的代码信任权限；浏览器声明和普通会话写权限不足以授予该权限。

公共 Host 激活路径在求值前执行策略，直接面板调用也包含在内。纯 Host 包使用现有卡片，结算时不装载 Client 源码。Client 对未来版本的授权与精确的 Host 授权相互独立。未配置策略的个人组合保留原生纯 Host 直接激活行为。

捕获的有限租约控制待完成激活和原生运行生命周期。原生停止、undefine、provider 撤销、到期和 runner 释放会阻止迟到的批准或待完成启动发布运行。原生 owner 在发布异步准入结果前取得清理所有权。普通 fiber 释放仍负责已挂载的 effect。

## 考虑过的替代方案

**仅使用通用一次性审批服务。** 其请求要求存在打开的轮次，而直接 Cordis 面板操作可以发生在轮次之外。它也无法推断部署的代码信任角色。现有精确包卡片覆盖这两条生命周期路径，无需添加另一套交互系统。

**仅安装审查插件。** 独立审查可以为人的决策提供依据，但审查提醒和审查结论不能确立经过身份验证的权限，也不能约束每一条原生激活路径。

**限制模型的插件目录。** 固定目录会移除动态 Cordis 能力，却不能隔离任意已接受的 Host 代码。显式受信任代码准入保留原生组合，并将不受信任的执行交给其执行 provider。

## 后果

部署可以保留动态 Host 插件，同时将代码信任与协作权限分开。provider 必须实现真实身份、当前角色检查以及精确源码授权。撤销会撤回原生 fiber 和 handler，但不会撤销先前任意 Node 副作用，也无法收回受信任代码刻意保留的引用。VM 仍不构成安全边界。

聚焦的原生 runner 和卡片测试使用伪策略 fixture，覆盖缺失与拒绝授权、精确版本、未来 Client 批准、到期、撤销、待满足注入以及迟到的 stop/undefine 结果。它们不证明部署的角色验证器或签名证明签发器。这些 owner 需要独立的联合验证。

所属应用的浏览器预期测试通过用户面板操作驱动实际构建的 Web Client 和原生 Host runner，然后撤销其有限期测试租约。测试检查操作前不存在 Host 副作用、策略接收准确且不可变的源码身份、撤销移除原生副作用，并且没有模型调用。Package 在 Client 首次读取清单之前创建；直接在注册表中定义本身不会发布工具卡片，也不会刷新已加载的清单。
