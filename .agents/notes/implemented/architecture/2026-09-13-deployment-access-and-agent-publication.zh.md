# Agent Note: 部署访问与 Agent 发布

Status: implemented

[English](2026-09-13-deployment-access-and-agent-publication.md) | 中文

## 问题

共享 Host 需要对原生一元调用、mux 流和审批回复实施绑定请求的授权。分页后过滤搜索结果可能隐藏可读结果。仅在 Agent 创建后分配权限会暴露发布前的所有权缺口，而等待持久追加的时间可能超过已检查授权的有效期。

## 决策

Gateway 从原始传输请求接收部署提供者的租约，检查分派和投递，并关闭已撤销的传输。原生 mux 和 RPC 编解码器保持不变。必需策略配置在没有提供者准入请求时拒绝访问。隐藏的瀑布投递会离开待处理记录，在没有实际接收者时委托后续处理。

SessionController 在原生列表收集和搜索分页前查询可见性提供者。AgentLoop 为每个创建路径组合部署准备与调用者设置，等待持久种子追加，同步提交，然后不再等待便发布。部署插件负责身份验证、不可变工作区映射、持久 ACL 和执行能力。

原生 Client 套接字工厂保留 Remote mux 帧协议，同时允许外壳获取每次尝试的新准入。取消会关闭异步工厂迟到的结果。[DeepTail](https://github.com/d4551/DeepTail) 在 `69696916832b02c0ecdd9ce625aeae93c7787cfc`（MIT）中记录了这个缺少的物理传输扩展；此实现添加原生钩子，而非复制其应用传输。

Open-in-app 在其原生路由所有者处授权宿主资源观察。部署租约授权一个规范化的启动目标；每次主要、后备和重新解析后的尝试都重新检查该目标及当前权限。将策略保留在启动器旁边，可以防止原生后备路径绕过仅在路由入口执行的检查。仅有浏览器认证并不授权工作区目录或宿主机器操作。准入所有权同时覆盖迟到的履行以及 Promise 交接期间的取消。

`prepare(agentCtx, agent, capabilities)` 的第三个参数是冻结的对象：`parent` 是工厂收到的显式父 Agent，不依赖环境中的 initiator 归因；`terminate` 是仅针对该 Agent 的权限终止能力。调用 `terminate()` 会同步停止当前工作，保留排队的 Inbox 输入，并开始原生的持久写入排空、作用域清理和注册表移除。它返回 `void`，因此 pre-step 监听器不会等待自身的清理；异步失败由工厂观察。重复调用共享第一次清理及其 Inbox 策略。旧能力不能终止从同一 Session 恢复的新 Agent。普通 `AgentHandle.dispose()` 若先发起清理，仍保持原有的清空 Inbox 行为。

Session 导出在返回流式响应前，从同一个可见性所有者捕获具有有限生命周期的读取器。捕获调用栈只会保留失效的环境槽位，而不是当前权限。因此读取器保留不可变的主体和请求生命周期，并重新读取各资源策略。发现后代关系并不授予继承的读取权限；附件流在每次块读取前后重新检查引用该附件的 Session 当前仍可读。撤销会使压缩包失败，而不是把部分导出表现为成功。

## 考虑过的替代方案

替换 RPC 解析器或镜像 Session 会创建相互竞争的原生行为。结果返回后过滤无法保护发布前事件，也无法恢复已被分页排除的搜索结果。仅依赖调用者设置会遗漏直接配置的 Agent。因此拒绝这些方案。

## 影响

独立配置保留现有行为。必需的部署提供者可以拒绝原生 Remote 流量和 Agent 发布，无需替换预设、模型选择或工具。Connection 还通过必需的部署请求策略对每个 HTTP RPC 通道和精确 Fetch 路由进行准入，在原生请求与响应流期间保留租约。Gateway 保留操作级检查。租约取消后立即释放权限，即使处理器或源忽略取消；迟到的响应体会被取消。单独注册的 WebServer 路由和 WebSocket 升级仍由其路由所有者负责。持久准备不具备跨服务原子性；其所有者必须协调中断的写入。浏览器认证和 Remote 事件决策仍然有效，并通过明确链接标注部分取代关系。

## 验证

定向原生测试和组合策略测试覆盖直接读取、流投递、审批回复、缺少权限、撤销、分页前可见性，以及实际持久追加之后的发布。源码所有者的 Loader 和构建验证另行记录准确结果。

已录制的 SDK deployment-termination 场景与 Python SDK 投影使用同一个原生生命周期插件：终止空闲 Agent、持久化待处理的 Inbox 输入、在同一 Session 上恢复不同的 Agent，并拒绝过期终止权限。原生 pre-step 测试覆盖主动取消且不会等待自身。Python 本地验证可以使用构建后的原生 Node CLI；打包单可执行文件验证仍是独立的 CI 层级。
