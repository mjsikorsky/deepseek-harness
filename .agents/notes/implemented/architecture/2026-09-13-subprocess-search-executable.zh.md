# Agent Note: 搜索可执行文件跟随子进程提供方

Status: implemented

[English](2026-09-13-subprocess-search-executable.md) | 中文

## 问题

搜索消费方通过原生子进程提供方启动 ripgrep，却在宿主上解析打包二进制。远程或容器提供方即使支持完整的原生子进程接口并拥有目标工作区，也无法执行该宿主路径。

## 决策

搜索包接受可选的 `executable` 名称或路径。glob 与 grep 都通过所选子进程提供方解析它，传入当前取消信号，再通过同一提供方启动。解析失败会使调用失败，不会回退到宿主二进制。省略该配置时保留打包二进制及单文件伴随文件的行为。

## 考虑过的替代方案

**改写路径或把宿主二进制复制进容器。** 这会让传输层负责此消费方的平台相关依赖，还可能选中与执行环境不兼容的二进制。

**用产品工具替换原生 glob 与 grep。** 这会重复实现现有消费方已负责的 schema、解析、保留和取消行为。

## 后果

使用配置可执行文件的部署方负责其版本及支持的 ripgrep 参数。原生工具保留现有参数、`--no-config`、错误类型、输出上限和结果语义。选择可执行文件既不授权工作区访问，也不建立跨提供方的文件系统对齐。原生消费方的定向测试覆盖两个工具、失败时无回退以及启动前取消；容器集成还验证了真实的提供方调用路径。
